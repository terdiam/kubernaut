Kubernaut

A native, multi-cluster Kubernetes desktop app for macOS, Windows and Linux, written in Rust. No telemetry, and it starts with no clusters connected.

Why

Kubernetes GUIs tend to break one of two ways: they hold the entire object list in the frontend and choke on a large cluster, or they read ~/.kube/config on launch and put every configured cluster one click away, production included. Kubernaut keeps all cluster state in Rust and draws it natively, so there is no web view to feed. The UI only ever asks for a page or subscribes to a delta stream, and it starts with no clusters connected; every one is added explicitly.

Features

Multi-cluster

Clusters are added explicitly, connect lazily, and protected ones refuse every change.

Resource browser

Full API discovery including CRDs, virtualised tables, row selection, and a command palette across clusters.

Create, edit, validate

Form or YAML with the cluster's own schema underlining mistakes, and a server-side diff before anything applies. Reference fields are read from the cluster.

Diagnose

Reads a pod's status the way a person would, quotes the cluster rather than guessing, and offers a next step into logs or a shell.

Logs and terminals

Multi-pod log tail, a shell in a pod, a debug container, a shell on a node, and port forwarding bound to loopback.

Topology and usage

Ingress to Service to Workload to Pod on a graph you can drag, with namespace usage against what is requested.

Nodes

Cordon, uncordon and drain with a preview, and edit labels and taints from the node's own tab.

Helm and GitOps

Every release read from the cluster, with a pre-upgrade diff, history and rollback.

Security Center

Workload posture checks, RBAC analysis and image CVEs. No scanner required for the first two.

Signed updates

Releases are signed, and the app checks the signature before it installs one. Installers for macOS, Linux and Windows.
